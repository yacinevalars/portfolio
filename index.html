🧑‍💻 Alternance — Architecture & implémentation (contexte anonymisé)

.NET · Clean Architecture · API REST · Blazor · CI/CD · OpenTelemetry

C# / .NET API REST EF Core SQL Server / PostgreSQL Blazor Autorisation par politiques Jobs asynchrones OpenTelemetry CI/CD Spécifications techniques

Architecture
Les applications sur lesquelles j’interviens sont structurées en Clean Architecture : une couche Domain contenant les entités métier sans dépendance externe, une couche Infrastructure regroupant l’accès aux données et les services techniques, et une couche API/Présentation exposant les fonctionnalités. Les endpoints REST suivent une organisation en vertical slices (une fonctionnalité = une unité auto-contenue avec sa requête, sa validation et sa réponse), avec un contrat d’API documenté (OpenAPI/Swagger) et un client typé généré automatiquement pour le frontend — l’objectif étant d’éviter toute duplication manuelle de DTO entre back et front. Chaque fonctionnalité importante démarre par une phase de spécification (rédaction d’un document de spec technique/fonctionnelle) avant le développement, pour clarifier le besoin et les critères d’acceptation. Qualité, intégration & observabilité
Les livraisons passent par une chaîne de CI/CD : build automatisé, exécution de la suite de tests, et déploiement automatisé — ce qui réduit les erreurs manuelles et fiabilise la mise en production. Les applications sont instrumentées avec OpenTelemetry pour générer des traces distribuées et des métriques, complétées par des logs structurés, permettant de diagnostiquer un incident en production et de suivre les performances dans le temps. Compétences techniques mobilisées

  • Rédaction de spécifications techniques/fonctionnelles avant développement.
  • Persistance de données relationnelles avec Entity Framework Core, migrations, modélisation de schémas.
  • Mise en place d’une autorisation fine par politiques (contrôle d’accès basé sur les rôles/attributs).
  • Développement d’interfaces web avec Blazor (composants réutilisables, gestion d’état).
  • Traitements asynchrones planifiés (jobs en arrière-plan) pour des tâches longues ou différées.
  • Génération de documents (export PDF/CSV) et automatisation d’imports de données.

📚 LearnHub (SAE BUT2) — Architecture & implémentation

Java 17 / Spring Boot · React 19 / TypeScript · PostgreSQL · Docker

Spring Boot 3 Spring Security + JWT Spring Data JPA React 19 + Vite TanStack Query Zustand Docker Playwright

Backend
API REST en Java 17 / Spring Boot 3.4, architecture en couches inspirée de l’hexagonale (API / Application / Domain / Infrastructure) avec inversion de dépendances — les interfaces de repository vivent dans le domaine, leurs implémentations en infrastructure. Authentification par JWT (access + refresh token via jjwt) avec filtre Spring Security custom, persistance PostgreSQL via Spring Data JPA (H2 pour les tests d’intégration). Documentation d’API avec springdoc-openapi / Swagger. Frontend
SPA React 19 / TypeScript construite avec Vite et Material UI, routing React Router v7. Gestion d’état séparée entre server state (TanStack Query) et état client (Zustand), formulaires typés avec React Hook Form + Zod, appels HTTP via Axios avec intercepteur de refresh automatique sur 401. Les types TypeScript sont générés directement depuis le contrat OpenAPI du backend (openapi-typescript) pour garantir la cohérence front/back.

  • Modules développés : cours/chapitres/ressources pédagogiques, inscriptions et suivi de progression élève, workflow de demande de compte avec validation admin, messagerie interne et signalement de contenu.
  • Infra : conteneurisation multi-services avec Docker / docker-compose (API + PostgreSQL + Mailpit pour les emails en dev).
  • Tests : unitaires Vitest + React Testing Library côté front, tests d’intégration Spring Boot sur H2 côté back, end-to-end Playwright sur les parcours critiques (login, gestion de cours, apprentissage élève).

Intelligence artificielle

🤖 Les agents IA changent la façon de coder

Les assistants et agents IA (autocomplétion avancée, génération de tests, revue de code assistée) sont en train de transformer le métier de développeur, pas seulement de l’accélérer. Ce qui m’intéresse, ce n’est pas tant l’outil que ce qu’il déplace : savoir cadrer une tâche pour un agent, relire son code avec un œil critique et rester capable de comprendre ce qui a été produit deviennent des compétences aussi importantes que savoir coder soi-même.

🔗 Source : github.blog/ai-and-ml
Sécurité

🔗 Les attaques par la chaîne d’approvisionnement logicielle

De plus en plus d’incidents de sécurité ne viennent plus d’une faille dans son propre code, mais d’une dépendance (librairie, package npm/NuGet) compromise en amont. En travaillant sur des applications qui manipulent des données sensibles, ça me pousse à rester vigilant sur les dépendances que j’intègre, et pas seulement sur le code que j’écris moi-même.

🔗 Source : owasp.org/www-project-top-ten
Écosystème .NET

⚙️ Le rythme annuel des versions de .NET

Microsoft publie une nouvelle version majeure de .NET chaque année, avec un cycle de support long/court en alternance (LTS/STS). Travaillant au quotidien dans cet écosystème, je suis les nouveautés de chaque version (performance, nouvelles API) pour savoir quand et pourquoi migrer un projet, plutôt que de rester par défaut sur une version ancienne.

🔗 Source : dotnet.microsoft.com
Langages

🦀 La montée des langages "memory-safe" (Rust)

Plusieurs grands acteurs (dont des agences gouvernementales) recommandent désormais de privilégier des langages qui éliminent par construction certaines failles mémoire (comme Rust), en particulier pour les systèmes critiques. Je trouve ce mouvement intéressant à suivre même sans coder en Rust au quotidien : il rappelle que le choix d’un langage est aussi un choix de sécurité, pas seulement de productivité.

🔗 Source : rust-lang.org
